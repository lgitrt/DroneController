# Drone Simulation: LQR Control & Performance Analysis

This project simulates a quadrotor (drone) with two linear feedback control strategies and compares their performance on circle-tracking tasks. The simulation uses a high-fidelity nonlinear dynamics model and allows rapid iteration on controller tuning.

## Overview

**Quadrotor Model:**
- 12-state nonlinear dynamics (position, attitude, linear/angular velocities)
- 4 rotor-speed inputs (squared rotor speeds, ω²)
- Linearized small-angle approximation valid around hover equilibrium

**Controllers:**
- **Aggressive LQR**: Prioritizes fast, accurate tracking with higher control effort
- **Conservative LQR**: Smooth, low-energy tracking with larger steady-state error

Both controllers use the same linearized hover model but with different Q and R weights in the LQR cost function.

**Reference Trajectory:**
- Smooth-start (quintic ramp) circular path
- Configurable radius, altitude, and angular velocity
- Tracks position (x,y,z) and attitude (roll φ, pitch θ, yaw ψ) via differential-flatness feedforward

## Usage

### Run the Full Comparison

```matlab
addpath('matlab');
run('matlab/run_controller_comparison.m');
```

This script will:
1. Load quadrotor parameters (`parameters.m`)
2. Design two LQR gains (Aggressive and Conservative)
3. Simulate both controllers on the circle-tracking task
4. Generate five comparison figures saved to `results/`
5. Print performance metrics to the console

### Expected Output

```
=== Tracking performance summary ===
                          Aggressive    Conservative
Overall RMSE                  0.0051          0.0266   [m]
RMSE x                        0.0008          0.0012   [m]
RMSE y                        0.0006          0.0011   [m]
RMSE z                        0.0088          0.0461   [m]
Mean control effort          11503.0          6483.1   [rad^2/s^2]
Done. Figures saved to results/
```

Aggressive LQR achieves ~5x lower RMSE but requires 1.8x higher control effort. Conservative LQR is safer for hardware with motor saturation or power limits.

### Customize the Trajectory

Edit `matlab/run_controller_comparison.m`:

```matlab
traj.radius   = 2;          % circle radius [m]
traj.omega    = 2*pi/30;    % angular velocity [rad/s]
traj.altitude = 2.5;        % hover altitude [m]
traj.rampTime = 5;          % smooth-start duration [s]
tEnd = 45;                  % total simulation time [s]
```

### Customize Controller Tuning

Create a new LQR gain in `matlab/designLQR.m`:

```matlab
K_custom = designLQR(p, 'Tuning', 'Aggressive');
% Available: 'Aggressive', 'Balanced', 'Conservative'
```

Or add a new custom tuning:

```matlab
case 'MyTuning'
    qPos   = [50 50 80];    % position weights
    qAtt   = [6 6 3];       % attitude weights
    qVel   = [2 2 3];       % velocity weights
    qRate  = [0.4 0.4 0.2]; % angular rate weights
    R_scale = 3e-11;        % input weight scale
```

## Theory

### Linearized Model

The quadrotor dynamics linearize around hover (x̃ = 0, all velocities = 0) as:

```
ẋ = Ax + Bu
```

where:
- **A** ∈ ℝ^(12×12) couples position/velocity to attitude, and attitude/angular rates
- **B** ∈ ℝ^(12×4) maps rotor commands → accelerations and torques

Key decoupled chains:
- **x-θ chain**: x-position controlled via pitch angle
- **y-φ chain**: y-position controlled via roll angle
- **z chain**: altitude controlled via total thrust
- **ψ chain**: yaw controlled independently

The system is **fully controllable** but **underactuated** (4 inputs for 6 translational/rotational DOF).

### LQR Design

Continuous-time optimal control minimizes:

```
J = ∫₀^∞ (x'Qx + u'Ru) dt
```

Subject to ẋ = Ax + Bu. The optimal state-feedback gain is:

```
K* = R⁻¹B'P
```

where P solves the continuous-time algebraic Riccati equation (CARE).

**Tuning strategy:**
- Increase Q weights → tighter tracking, more control effort
- Increase R weights → smoother inputs, more tracking error
- The ratio Q/R determines the aggressiveness

### Feedforward from Differential Flatness

The quadrotor is **differentially flat** in position (x, y, z). Given a desired position trajectory and its derivatives, we can compute reference attitude angles:

```
φ_ref = -aₓ / g  →  pitch angle for x-acceleration
θ_ref = aᵧ / g   →  roll angle for y-acceleration
```

This feedforward significantly reduces tracking error without relying purely on feedback.

## Nonlinear Simulation

The controllers are applied to the **full nonlinear model** (`QuadrotorStateFcn.m`), not the linearized approximation. This validates robustness and reveals limitations when tracking large-angle maneuvers or near motor saturation.

Integration uses Runge-Kutta 4th-order with adaptive sub-stepping for accuracy.

## Performance Summary

**Aggressive LQR:**
- Excellent trajectory tracking (0.5 cm RMSE overall)
- Fast transient response
- High motor duty cycle (not recommended for weak batteries)
- Sensitive to model mismatch and sensor noise

**Conservative LQR:**
- Smooth, safe operation (2.7 cm RMSE overall)
- Low energy consumption
- Graceful degradation with wind/disturbances
- Recommended for deployed systems

## Extending the Project

### Add Disturbance Rejection
Modify `simulateClosedLoop.m` to add wind or measurement noise:

```matlab
wind = [0.5; 0; 0];  % wind in x-direction
xdot_plant = QuadrotorStateFcn(x, u) + wind_effect;
```

### Add Integral Action
Modify the control law to include integral error:

```matlab
eint = eint + (x - xref) * Ts;
u = u_hover - K*(x - xref) - Ki*eint;
```

### Experiment with Nonlinear MPC
The template `designNMPC.m` can be debugged further by:
- Relaxing output constraints
- Reducing prediction horizon
- Using reference trajectory tracking instead of absolute position

### Validate on Hardware
Export gains and reference generator to C code:

```matlab
codegen designLQR -args {p} -o matlab/designLQR_gen
```

## Troubleshooting

**Q: Plots don't appear / MATLAB warns about graphics**
A: The script saves figures to `results/` even without displaying. Check the PNG files directly.

**Q: Simulation is very slow**
A: Increase the sample time `Ts` in `run_controller_comparison.m` or reduce `tEnd`. LQR is real-time capable; the bottleneck is plotting.

**Q: LQR tracking error is large**
A: Increase the position weights `qPos` in `designLQR.m`, or use Aggressive tuning.

**Q: Motors saturate (commands exceed wMax²)**
A: Reduce reference trajectory speed, or switch to Conservative tuning.
